# Zotero 标注—最终笔记覆盖审计

## 目的

确认最终笔记完整保留用户在 Zotero 中标出的内容和思考。高亮原文可概括，用户文字批注则优先保留原话、术语和理解顺序，轻度润色并紧邻补必要解释。审计同时检查语义充分性与表达保真度：只在别处散落相关信息、或用抽象总结替代用户理解，不算充分覆盖。

审计执行两次：

1. 去 AI 味润色完成后、写入飞书之前。
2. 飞书写入后重新读取文档，确认排版或局部更新没有丢失内容。

## 审计输入

- 当前论文 PDF 和论文地图。
- 最新 Zotero 标注快照：标注 key、颜色、页码、类型、文字、批注和原文上下文。
- 语言审校后的最终笔记草稿，或飞书文档最新内容。
- 用户明确要求保留的人工修改和例外说明。

重新运行提取脚本获取新快照；不要依赖第一次阅读时缓存的标注，因为用户可能在期间增加、删除或改色。

## 每条标注的状态

为每条有标注文字或批注的记录登记以下状态之一：

| 状态 | 判定标准 |
|-|-|
| `正文已体现` | 核心含义已经在相关段落中直接表达 |
| `已保留并解释` | 批注原意和表达线索在相关位置作为完整段落或高亮块保留，必要答案、前提和推导紧邻，读者能辨认用户关注的关系 |
| `已转化呈现` | 内容通过公式、表格、流程或图片分析表达，正文能看出其作用 |
| `旁路已保留` | 重要疑点、争议、缺陷、错误或延伸知识以相邻批注/提示块保留 |
| `重复/无独立信息` | 与另一条标注完全重复，或仅是已覆盖内容的短重叠；必须记录对应主标注 key |
| `部分体现` | 已有相关内容，但批注被拆散、只剩结论，或遗漏独立条件、推理、问题答案；仍须列缺口 |
| `尚未体现` | 核心意思、问题、条件或批判在最终笔记中没有落点 |

不要使用“关键词出现”作为唯一依据。出现同一个术语但没有解释标注所指关系，仍属于尚未体现。

## 关键理解的充分阐述

如果批注文字已经包含用户自己的推理、比较、计算、机制判断或设计取舍，覆盖判定必须检查完整解释链：

```text
批注中的现象/前提
→ 为什么这样理解
→ 对应的机制或推导
→ 得出的结果与影响（仅在必要时补适用条件）
```

如果批注包含多个相互关联的判断，却只保留“所以方法有效”“这是一个瓶颈”之类的结论，不能标记为“正文已体现”或“已保留并解释”。如果批注本身只是一个单一判断，简明直接地表达即可。可以去掉重复措辞、改变句式或拆分段落，但不得把原本明确的理解改成需要读者猜测的暗示。

## 按颜色审计

### 蓝色与黄色

- 逐条确认关键论点、机制、条件、数字或定义已经进入正文主线。
- 黄色可以普通正文、加粗、下划线、表格或提示块呈现；格式不同不影响覆盖判定。
- 若同一主张被多条连续标注覆盖，可以合并，但要确认完整语义没有被删短。

### 紫色与历史洋红色

- 检查问题是否得到具体回答，而不是只把问题原文复制到笔记。
- 机制问题放在机制段，公式问题放在公式附近，实验口径问题放在评估段；保留批注问法或关键理解，并让问题与解释形成相邻、完整的单元，不拆散混入其他内容。
- 重要但无法解决的问题使用“旁路已保留”，并说明缺少什么信息。
- 如果紫色批注已经包含关键理解，检查正文是否直接说清其中实际包含的推理和判断；不能用间接转述或含糊提示代替。

### 绿色

- 检查局限是否写在对应假设、方法或实验语境附近。
- 不能用文末一句泛泛的“存在局限”代替具体缺陷。

### 红色

- 检查是否记录原表述、复核过程得到的结论、修正内容和影响范围。
- 未能确认时必须保留为存疑，不能把红色标注直接改写成确定错误。

### 橙色

- 检查必要的追溯知识是否已经补进正文或作为相邻学习线索。
- 需要保留的待深入事项、扩展阅读和可追溯资料应进入独立的“第四章：待深入与可追溯线索”，不混入结果评估。
- 无关扩展不必硬塞进笔记，但要在审计记录中说明不保留的原因。

## 通过条件

满足以下条件才允许进入飞书写入：

- 所有重要蓝色和黄色标注不处于“部分体现”或“尚未体现”；未经用户接受的缺口须报告，不能宣称全部覆盖。
- 所有非空紫色批注都已保留问题或理解线索，并相邻回答、旁路保留或明确说明无法确认。
- 文字批注的原意、术语、例子和理解顺序尽可能保留，扩展解释紧邻；未被拆散、过度概括或语言润色削弱。事实纠正有清楚依据。
- 分别报告全部高亮／下划线与非空文字批注的覆盖；部分体现单列缺口，禁止把主题出现或相邻输入输出描述当作充分解释。
- 没有为了审计通过而增加大量边界提醒；只保留影响准确性或理解的必要限定。
- 绿色、红色和橙色标注均有合理的相关位置或审计说明。
- 用户通过 `ask_question` 确认的呈现形态（正文段落 / 高亮块 / 存疑块 / 第四章专题）在最终笔记中得到了精确执行，未发生违背用户选择的形式漂移。
- 存在实质待深入或可追溯内容时，已创建独立第四章；无内容时未保留空章节。
- “重复/无独立信息”记录了对应的主标注 key。
- 审计结果能够列出未覆盖项；未覆盖项为空，或用户已明确接受并排除。

## 审计结果的内部格式

不必把完整审计表写进最终笔记，但应保留以下最小信息供写入后复核：

```text
annotation_key | color | page | status | note_location | reason_or_action
```

对外只报告真正需要用户处理的缺口、被排除的低信息标注和仍未解决的问题，不展示冗长的后台流水账。
