# Zotero 标注路由

## 颜色语义

| 颜色 | Hex | 用户语义 | 默认处理 |
|-|-|-|-|
| 蓝色 | `#2ea8e5` | 论文关键点 | 进入正文主线，重点解释其因果作用 |
| 黄色 | `#ffd400` | 强调内容 | 同样进入正文主线；按重要性适度突出 |
| 紫色 | `#a28ae5` | 疑问/关键理解 | 回到全文求解，保留问题或理解线索，在相关位置完整呈现 |
| 历史洋红色 | `#e56eee` | 疑问/关键理解 | 与紫色统一处理 |
| 绿色 | `#5fb236` | 论文缺陷 | 放在相关方法、假设或评估附近 |
| 红色 | `#ff6666` | 疑似论文错误 | 独立复核后就地说明 |
| 橙色 | `#f19837` | 可追溯知识 | 补充必要背景或形成延伸线索 |

颜色只表示处理意图，不取代对原文语义的判断。

## 蓝色与黄色：共同组成主线

- 将两类标注与论文地图合并，按论文叙事排序，不按颜色分节。
- 蓝色通常承担关键论点、机制或结论；黄色常承担定义、条件、数据和需要记住的细节，但黄色也可能是主线核心。
- 黄色的强调格式从弱到强选择：正文 → **加粗关键短语** → 表格关键单元格 → 提示块。不要把每条黄色标注都做成提示块。
- 合并相邻或重复标注，保留最完整的上下文和最精确的表述。

## 紫色：先解决，再决定呈现形态

在后台为每个问题记录：原文位置、问题本质、回答、置信边界、正文落点。

- 文字批注优先保留用户原话、术语、例子与理解顺序；只修正笔误、改善句式并补必要前提和推导。在相关小节用一个完整段落或高亮块呈现，避免将一条批注拆散到多个论述中。
- **关键机制理解**：保留问题的核心问法或判断线索，紧邻补出机制解释。可改为简短主题句，无需强制使用或删除“问：/答：”；最终能辨认出用户原本关注的关系。
- **公式或数据流问题**：紧邻公式、流程或图表解释。
- **评估口径问题**：放入实验设置、基线或结果分析。
- **独立批判或重要延伸**：使用旁路批注/提示块。
- **证据不足**：明确保留为存疑点。

只有用户明确要求逐题回答，或问题彼此独立无法自然融合时，才输出单独问题清单。

## 绿色、红色与橙色

- **绿色（局限性与缺陷）**：区分作者承认的局限、实验暴露的边界和用户提出的批判；不要笼统写“存在局限”。
  - **原论文有独立局限性章节（如 Limitations / Discussion）时**：必须在笔记“第三章：结果与评估”末尾保留独立完整小节（如“三、（四）局限性与失效边界”），系统复现作者承认的算力/数据/适用场景瓶颈、破坏性实验边界与未闭合假设，**严禁拆碎稀释融入正文各部分**；
  - **原论文无独立章节时**：方可就近放在相关方法、假设或评估附近呈现。
- **橙色（#f19837，可追溯知识 / Follow-up）：逢橙必派独立 Subagent 搜索 + “被引机理 → 反观本文”闭环**：
  用户标记橙色意在追溯论文引用的先驱方法或外部概念，并根据其真实机理反观论文本身。**无视论文篇幅阈值（哪怕正文 $\le 15$ 页单 Agent 精读），只要存在橙色标注，必须强制按 [subagent-orchestration.md](subagent-orchestration.md) 第四节派生独立的【橙色溯源调研 Subagent】执行外部搜索与按需多轮追问**，隔离搜索噪音并完成以下三步内容闭环：
  1. **双重语境锚定（Context & Citation Grounding）**：结合本篇核心主线、橙色标注所在完整自然段、用户批注原话及 References 完整引文信息，锁定作者引用意图与用户的具体技术好奇点（如底层数学推导、延时/存储开销、微架构瓶颈）；
  2. **追溯外部真实机理（The Former：深入被引机理）**：由【橙色溯源 Subagent】调用联网与学术检索工具（`search_web` / `academic-search`），查明被引文献或外部技术的真实核心设计、数学/硬件模型、实测结论与固有瓶颈，严禁凭原文表面一句话引述或预训练记忆脑补；
  3. **反观本文折中与局限（The Latter：反观对比与反思）**：基于外部真实机理反观本篇论文：① **设计动机映射**（本篇如何针对上述瓶颈做出架构选择或改造）；② **工程折中与脆弱性反思**（结合用户批注批判性分析本篇做法付出的新代价、硬件开销或极端工况/OOD 泛化边界）；③ 按属性或用户 `ask_question` 裁决，收敛整合进“第四章：待深入与可追溯线索”独立专题或就近作为旁路提示块呈现（主 Agent 审阅时首轮达标即放行，深度不足或有新对比线索时通过 `send_message` 发起按需多轮追问重查）。

## 旁路高亮块 vs 融入正文：交互决策协议（ask_question）

在进入成文或制定计划时，严禁 AI 擅自替用户裁决关键深度批注的版面形态。针对具有呈现双重性（既可作为正文逻辑段落，又可作为独立高亮块/提示块）的高价值点，必须调用 `ask_question` 工具向用户征询呈现偏好。

### 1. 触发场景与必问规则

在进入成文或制定计划时，**严禁 AI 擅自替用户裁决橙色标注与深度批注的版面形态**。为保证阅读心流并杜绝多轮碎片化弹窗打扰，主 Agent 必须在制定计划阶段，**将全部候选问题打包在单次 `ask_question` 调用中集中向用户提问裁决**：

1. **【强制必问】所有橙色标注（#f19837，逢橙必问）**：
   - 只要存在橙色标注，**必须逐条向用户提问裁决其落点走向**（无论篇幅长短、无论橙色标注有多少条，严禁 AI 擅自替用户划归第四章或正文）；
   - **裁决核心**：该外部技术/被引文献是收敛至【第四章：待深入与可追溯线索】独立专题，还是就近作为当前章节的【💡 延伸背景/对比】旁路提示块？
2. **【重点筛选】关键争议批注（复合紫色、架构对比、红色存疑）**：
   - 不设人为“1~4 个”数量上限卡死，凡符合下表特征的关键争议点，一并打包进同一次 `ask_question` 集中请示；
3. **【常规免问】纯蓝色主线事实与单一黄色加粗**：
   - 纯事实叙述、单一黄色加粗、基础术语定义、纯图表引述等，遵循默认规则直接融入正文，无需提问。

| 争议场景 | 典型特征 | 裁决核心（向用户征询什么） | 问询性质 |
| :--- | :--- | :--- | :---: |
| **高价值延伸线索（橙色）** | 被引文献机理、外部先驱工作、学科交叉线索 | **收敛进【第四章：待深入与可追溯线索】独立专题，还是就近作为当前小节的旁路提示块？** | **强制必问**<br/>(逐条全问) |
| **复合型紫色批注** | 批注包含“前提 → 机制 → 例子/反例 → 取舍”多层逻辑 | 作为小节自然段，还是保留为醒目的【💡 关键理解】高亮块？ | 重点筛选 |
| **架构取舍与批判性反思** | 批注涉及跨领域对比（如对标其他论文/同类 ASIC 缺陷） | 融入当前硬件模块正文，还是作为独立的旁路对比高亮块？ | 重点筛选 |
| **疑似错误 / 存疑推导（红色）** | 发现符号丢失、位宽溢出或公式存疑，但论文未开源验证 | 就地给出条件限定正文，还是作为独立的【🔍 存疑】提示块？ | 重点筛选 |

### 2. ask_question 调用规范

调用 `ask_question` 时必须严格遵守以下格式要求：

- **题干（question）结构**：必须包含 `[页码/小节定位]` + `[用户原始批注摘要]` + `[呈现争议焦点]`；
- **选项（options）结构**：
  - 第 1 个选项必须是 `(Recommended) [推荐选项]：[专业推荐理由]`；
  - 提供 2~3 个具体、互斥的排版走向选项（如：融入正文自然段落、独立【💡 关键理解】高亮块、独立【🔍 存疑】提示块、收敛入第四章专题）；
  - `is_multi_select` 设为 `false`。

### 3. 决策闭环与落地

用户完成选择后：
1. **固化记录**：后台在审计映射表中登记为：`annotation_key -> user_selected_format`；
2. **大纲体现**：在笔记大纲与计划输出中，明确标注该点采用的版面形式（如标注 `[高亮块-关键理解]` 或 `[正文自然段]`）；
3. **XML 精确兑现**：在生成飞书 XML 时，严格使用 `<callout>` 或 `<p>`，杜绝后续擅自篡改。

## 交接到最终审计

完成颜色路由后，使用 [annotation-audit.md](annotation-audit.md) 对每条标注做最终覆盖检查。该审计负责判定正文落点、关键理解是否直接阐述、问题是否得到回答，以及重复标注是否可以合并；不要在此处重复维护另一份覆盖清单。
