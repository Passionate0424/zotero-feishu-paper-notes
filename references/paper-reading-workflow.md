# 论文原文精读流程

## 原则

先建立对全文的独立理解，再叠加用户标注。标注决定关注权重，不决定论文事实，也不能替代没有被标注但不可缺少的前提、方法和实验信息。

## 0. 准备

1. 唯一定位论文条目和 PDF 附件。
2. 核对标题、作者、年份、会议/期刊和版本；预印本与正式版并存时说明所读版本。
3. 确认 PDF 页数、文本是否可提取、公式和图表是否需要页面渲染。
4. 暂存 Zotero 标注，但先不据此下结论。

## 1. 第一遍：恢复论文自己的逻辑

依次阅读并记录：

1. **摘要与引言**：问题、动机、现有不足、作者宣称的贡献。
2. **相关工作**：本文与直接前作的边界；只保留对论文定位有用的关系。
3. **预备知识/问题定义**：符号、输入输出、假设、约束和评价目标。
4. **方法**：总体架构、模块依赖、训练/推理顺序、数据流、算法步骤。
5. **公式**：每个变量是什么、公式解决哪一步、成立需要什么前提。
6. **图表**：坐标、图例、比较对象、正文如何解读、图表与结论是否一致。
7. **实验**：模型/数据集、基线、指标、精度、实现平台、归一化口径。
8. **结果**：主结果、消融、敏感性、失败案例和性能瓶颈是否迁移。
9. **结论与局限**：作者明确承认的边界，以及由实验能够直接看出的边界。

形成一条论文地图：

**针对常规研究型论文（因果推进链）**：
```text
研究问题
→ 为什么已有方案不够
→ 作者如何引出核心思想
→ 各模块按什么依赖顺序工作
→ 实验逐层验证了什么
→ 结论在哪些条件下成立
```

**针对综述型论文（分类学与演进拓扑）**：
```text
领域演进背景与痛点
→ 核心分类学准则 (Taxonomy)
→ 各流派技术路线分支 (分支机制/代表作/优劣)
→ 跨流派多维横向对比矩阵
→ 开放挑战与未来趋势
```

不要因为某段没有高亮就跳过它。若缺少该段会导致后文机制或结果无法自洽，它必须进入论文地图。

## 2. 第二遍：带着标注重读

1. 将标注定位到原页和完整上下文；至少读完包含它的自然段、相关公式或图表说明。
2. 判断标注承担的角色：建立背景、支撑主线、解释机制、验证结果、指出边界、提出问题或延伸知识。
3. 将蓝色、黄色内容嵌回论文地图，而不是另建摘录列表。
4. 将疑问映射到能回答它的原文位置；答案可能分散在多个章节。
5. 检查批注是否与论文原文、公式或图表冲突。用户批注是待核验的理解，不自动视为事实。
6. 补上用户未标注但回答问题所必需的中间推导。

## 3. 图、表、公式与事实后台核验准则

把核验放在后台完成。最终笔记直接、自然地解释论文，避免反复写“论文原文指出”“有直接证据”“根据表格可知”。只在自行计算、推断前提、纠错、指标口径或真实未知会影响理解时，就地简短说明一次；不给每段加边界或免责声明。

### 后台核验与外部检索优先级
1. 原文段落及其前后文 → 2. 关联公式、图、表、脚注和附录 → 3. 作者代码、补充材料或正式勘误 → 4. 官方标准、芯片/框架手册和 API 文档 → 5. 被论文明确引用的原始研究 → 6. 可靠二手技术资料（仅辅助理解，不写成论文主张）。最终正文只保留结论和必要链接，不写检索流水账。

### 事实、数值与推导边界
- 不把参数符号擅自替换为具体数值；论文只写位宽 `B` 时，不默认 `B=8`。
- 不把不同指标相互替代（例如 bit sparsity $\neq$ element sparsity）。
- 不把相关性、相似度或消融结果写成论文未证明的因果关系。
- 自行计算时写清输入数据、公式、单位、舍入方式和适用条件；从图中估读数值时使用“约”，避免制造超过图像分辨率的精度。
- 推断成立依赖额外假设时，把假设与结论写在同一处；论文和公开材料都未说明时，直接写“论文未说明”或“现有材料无法确认”。

### 公式、实现与图表核对
- 公式不得只转录：逐项检查符号、上下标、维度和单位，说明输入、输出、运算顺序和它在完整方法中的位置。
- 区分数学恒等式、论文近似、硬件化简和实现启发式；化简涉及平方、绝对值、量化、截断或符号位时检查信息是否丢失。
- 区分算法并行、硬件流水、batch 并行和时间上的重叠（不要只用“并行执行”一笔带过）；区分论文宣称的实现与根据架构图推测的实现。
- 优先选择承载整体架构、关键机制、主要结果或重要消融的图表；先写清它要解释的论点，保留原图号和 PDF 页码，裁切时保留图例、坐标、标注及必要上下文。图中文字与正文冲突时回查原 PDF，不依赖 OCR 猜测。

### 关键插图提取策略（arXiv HTML 优先）

为保障飞书笔记中架构图与数据图的高清呈现，提取论文图片时按以下优先级执行：

1. **第一优先级（arXiv HTML 原图提取）**：
   - 检查 Zotero 条目的 `url` 或 `extra` 字段。凡包含 `arxiv.org/abs/...` 或 `arXiv: yymm.xxxxx` 标识，提取其规范的 arXiv ID。
   - 直接访问 `https://arxiv.org/html/<arxiv_id>` 页面，解析 `<figure>` 节点，下载作者在 LaTeX 源码中上传的原生高清插图（PNG/SVG）至当前工作目录的 `./figures/` 目录。
   - 同步读取节点内的 `<figcaption>`，直接提取原图标题与上下文解释，免去计算 PDF 裁切坐标。
2. **第二优先级（本地 PDF 提取保底）**：
   - 若论文不属于 arXiv 预印本，或该篇论文在 arXiv 尚未生成 HTML 页面，回退至本地 PDF 文件，使用 PDF 工具提取原始图像流或进行页面区域裁切。

### 疑似错误（红色）与缺陷（绿色）核验
- **处理红色标注**：① 原样还原论文公式、图注或数据口径 → ② 给出最短可复核的反例、维度检查或数值推导 → ③ 检查是否存在版本差异、排版错误或术语歧义 → ④ 结论成立后，说明错误会影响公式、实现还是仅影响文字表述 → ⑤ 若无法定论，保留为存疑，不写成确定错误。
- **处理绿色标注**：说明缺陷对应的前提、基线、数据集、硬件条件或泛化范围，避免抽象批评。

## 4. 原文不可用

按以下顺序恢复：

1. Zotero 本地 PDF 附件。
2. Zotero 索引全文与 PDF 页面渲染互相校验。
3. 扫描页 OCR，并对公式、上下标和表格进行视觉复核。
4. 用户提供的其他合法版本。

仍无法读取关键部分时，明确列出缺失页或章节并停止正式总结、计划或写入。不得用摘要、批注、搜索摘要或二手介绍冒充全文阅读。

## 5. 完成标志

只有同时满足以下条件，才算完成精读：

- 能不依赖标注复述论文的因果主线。
- 能解释关键模块为什么按当前顺序出现。
- 能说明主要实验分别验证了哪项主张。
- 能指出结论适用范围和仍未闭合的问题。
- 所有重要标注均已得到正文位置、结论或明确的未解决状态。

## 6. 论文—笔记逻辑顺序审核

在写入飞书前，将论文地图与笔记大纲逐项映射。检查的对象不只是标题顺序，而是论证和依赖关系：

```text
原文叙事节点 | 它解决/承接的问题 | 笔记位置 | 是否保持顺序 | 必要的调整原因
```

至少映射：问题提出、问题分析或观察、技术一、技术一留下的新瓶颈、后续技术、实验验证、结论边界。

### 允许的调整

- 为“背景—贡献—评估”三大部分归类。
- 合并原文重复说明。
- 将后文反复依赖的定义或符号前置到首次使用前。
- 将实验设置集中到结果部分，但保留实验验证各主张的顺序。

### 不允许的调整

- 把“问题 → 技术 → 新问题 → 后续技术”压成互不相关的贡献列表。
- 在读者尚未知道前提时，先给出依赖该前提的机制、结论或图表解释。
- 将后续技术写在它解决的瓶颈之前。
- 按性能数字重新排序实验，破坏论文原本的验证链。

审核通过的标准是：笔记可以比原文更清楚、更紧凑，但读者仍能沿笔记复述出论文为什么按这个顺序提出每一步。若做不到，先重排大纲或段落，不用泛泛过渡语掩盖断裂。
