# 论文原文精读流程

## 原则

先建立对全文的独立理解，再叠加用户标注。标注决定关注权重，不决定论文事实，也不能替代没有被标注但不可缺少的前提、方法和实验信息。

## 0. 准备

1. 唯一定位论文条目和 PDF 附件。
2. 核对标题、作者、年份、会议/期刊和版本；预印本与正式版并存时说明所读版本。
3. 确认 PDF 页数、文本是否可提取、公式和图表是否需要页面渲染。
4. 暂存 Zotero 标注，但先不据此下结论。

## 1. 第一遍：恢复论文自己的逻辑

依次阅读并记录：

1. **摘要与引言**：问题、动机、现有不足、作者宣称的贡献。
2. **相关工作**：本文与直接前作的边界；只保留对论文定位有用的关系。
3. **预备知识/问题定义**：符号、输入输出、假设、约束和评价目标。
4. **方法**：总体架构、模块依赖、训练/推理顺序、数据流、算法步骤。
5. **公式**：每个变量是什么、公式解决哪一步、成立需要什么前提。
6. **图表**：坐标、图例、比较对象、正文如何解读、图表与结论是否一致。
7. **实验**：模型/数据集、基线、指标、精度、实现平台、归一化口径。
8. **结果**：主结果、消融、敏感性、失败案例和性能瓶颈是否迁移。
9. **结论与局限**：作者明确承认的边界，以及由实验能够直接看出的边界。

形成一条论文地图：

```text
研究问题
→ 为什么已有方案不够
→ 作者如何引出核心思想
→ 各模块按什么依赖顺序工作
→ 实验逐层验证了什么
→ 结论在哪些条件下成立
```

不要因为某段没有高亮就跳过它。若缺少该段会导致后文机制或结果无法自洽，它必须进入论文地图。

## 2. 第二遍：带着标注重读

1. 将标注定位到原页和完整上下文；至少读完包含它的自然段、相关公式或图表说明。
2. 判断标注承担的角色：建立背景、支撑主线、解释机制、验证结果、指出边界、提出问题或延伸知识。
3. 将蓝色、黄色内容嵌回论文地图，而不是另建摘录列表。
4. 将疑问映射到能回答它的原文位置；答案可能分散在多个章节。
5. 检查批注是否与论文原文、公式或图表冲突。用户批注是待核验的理解，不自动视为事实。
6. 补上用户未标注但回答问题所必需的中间推导。

## 3. 图、表与公式

- 优先选择承载整体架构、关键机制、主要结果或重要消融的图表。
- 不因图“看起来重要”就插入；先写清它要解释的论点。
- 保留原图号和 PDF 页码；裁切时保留图例、坐标、标注及必要上下文。
- 图中文字与正文冲突时回查原 PDF，不依赖 OCR 猜测。
- 公式不得只转录。说明输入、输出、变量、运算顺序和它在完整方法中的位置。

## 4. 原文不可用

按以下顺序恢复：

1. Zotero 本地 PDF 附件。
2. Zotero 索引全文与 PDF 页面渲染互相校验。
3. 扫描页 OCR，并对公式、上下标和表格进行视觉复核。
4. 用户提供的其他合法版本。

仍无法读取关键部分时，明确列出缺失页或章节并停止正式总结、计划或写入。不得用摘要、批注、搜索摘要或二手介绍冒充全文阅读。

## 5. 完成标志

只有同时满足以下条件，才算完成精读：

- 能不依赖标注复述论文的因果主线。
- 能解释关键模块为什么按当前顺序出现。
- 能说明主要实验分别验证了哪项主张。
- 能指出结论适用范围和仍未闭合的问题。
- 所有重要标注均已得到正文位置、结论或明确的未解决状态。

## 6. 论文—笔记逻辑顺序审核

在写入飞书前，将论文地图与笔记大纲逐项映射。检查的对象不只是标题顺序，而是论证和依赖关系：

```text
原文叙事节点 | 它解决/承接的问题 | 笔记位置 | 是否保持顺序 | 必要的调整原因
```

至少映射：问题提出、问题分析或观察、技术一、技术一留下的新瓶颈、后续技术、实验验证、结论边界。

### 允许的调整

- 为“背景—贡献—评估”三大部分归类。
- 合并原文重复说明。
- 将后文反复依赖的定义或符号前置到首次使用前。
- 将实验设置集中到结果部分，但保留实验验证各主张的顺序。

### 不允许的调整

- 把“问题 → 技术 → 新问题 → 后续技术”压成互不相关的贡献列表。
- 在读者尚未知道前提时，先给出依赖该前提的机制、结论或图表解释。
- 将后续技术写在它解决的瓶颈之前。
- 按性能数字重新排序实验，破坏论文原本的验证链。

审核通过的标准是：笔记可以比原文更清楚、更紧凑，但读者仍能沿笔记复述出论文为什么按这个顺序提出每一步。若做不到，先重排大纲或段落，不用泛泛过渡语掩盖断裂。
