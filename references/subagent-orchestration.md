# 多 Agent 三步双向闭环编排与动态角色划分规范

当精读长篇论文或高密度批注论文时，为避免单 Agent 上下文膨胀导致后期幻觉、公式失真或遗漏批注，采用**“主 Agent 轻量统筹 + Subagent-0 全局脉络 + 局部 Subagents 分段深潜”**的三步双向闭环架构。

---

## 一、 启用条件与 `ask_question` 交互确认机制

### 1. 触发检测（Step 1 定位论文后）
主 Agent 先运行 `extract_zotero_annotations.py` 获取标注 JSON，并仅读取 PDF 的**总页数、目录大纲/各级标题、摘要与结论**（保持主 Agent 初始上下文极度轻量）。满足以下任一条件时触发多 Agent 建议：
- **篇幅阈值**：PDF **正文页数 $> 15$ 页**（或含附录总页数 $> 20$ 页）；
- **高密批注阈值**：Zotero 标注总数 **$> 35$ 条**，或非空文字批注/疑问 **$> 10$ 条**；
- **复杂综述/软硬协同长文**：大部头综述论文（Survey / Review），或同时涵盖数学理论推导、硬件微架构（PE/Cache/流水线）与编译器调度的跨层长文。

### 2. 必须通过 `ask_question` 向用户建议并询问
达到上述阈值（或主 Agent 评估认为有必要开启）时，**严禁静默开启或静默单干**，必须调用 `ask_question` 向用户发起询问：
- **题干**：说明当前论文正文页数、Zotero 标注数量，并给出针对本文结构量身定制的 Subagents 切分方案建议；
- **选项 1**：`(Recommended) 开启 Subagents 三步协同精读：按 [1全局 + N局部定制方案] 切分，兼顾全局视野与局部零幻觉精度`
- **选项 2**：`保持单 Agent 顺序精读：由主 Agent 独立通读全文并撰写`

## 二、 Subagents 划分原则与参考职责矩阵

> [!IMPORTANT]
> **全局视野与动态择优双原则**：
> 1. **必配【Subagent-0 全文脉络专员】**：分段切分最忌“只见树木不见森林”。凡开启多 Agent 模式，必须配备一个通观全文的 `Subagent-0`，专职把握全局论证链、跨章节隐性耦合、全局统一符号表与跨页疑问定位，与死磕局部公式/微架构的局部专员形成互补。
> 2. **切分方案因文制宜（非固定教条）**：下表中的模式 A 与模式 B **仅为典型参考建议**。实际执行时，主 Agent 必须根据论文的**真实章节结构、页码重心、软硬件侧重与批注密集度**择优动态设计切分方案（例如：纯算法论文无需硬件专员；三阶段流水线系统可按阶段切分；实验占半壁江山的论文可拆分为主实验与消融两个专员）。

### 典型参考模式 A：常规研究型长文 —— “1 全局 + N 局部（通常 2~3 个）+ 1 可选溯源”

| Subagent 角色（参考建议） | 负责原文范围 | 第 1 步任务（精读上报《情报卡》） | 第 3 步任务（依指令写《章节高密稿》） |
| :--- | :--- | :--- | :--- |
| **Subagent-0**<br/>`全文脉络与全局视角专员`<br/>*(必配：提供上帝视角)* | **通览全篇正文**<br/>*(重宏观叙事与跨节关联，不抠局部繁琐推导)* | 1. 建立全景论文地图（Paper Map），理清“问题 → 方法一 → 新瓶颈 → 方法二”完整接力链；<br/>2. 识别跨章节强耦合点（如第 3 节假设如何决定第 5 节硬件折中）；<br/>3. 制定《全局统一符号与术语基准表》；<br/>4. 为全篇跨页紫色疑问定位答案所在页码与章节。 | 产出**开篇 `🎯 论文主线` Callout 初稿、开篇飞书原生思维导图（`mindmap`）代码，以及各章节交界处的承上启下过渡指引**（也可在 Step 2 汇报后由主 Agent 直接吸收撰写）。 |
| **Subagent-1**<br/>`背景与动机专员` | Abstract、Intro、Background、Motivation 实测观察、Related Work | 提炼场景需求、传统方案架构瓶颈与实测痛点数据；解析本区标注并标记跨区悬念。 | 按分配字数（参考 15%~20%，1.5k~2k 字）与用户排版选择，产出**第一章《背景知识与问题定义》** XML 片段与对比表。 |
| **Subagent-2**<br/>`核心方法与架构专员`<br/>*(若方法极长或含算法+硬件两大块，可择优拆为 2A 与 2B)* | Overview、核心算法/数学推导、硬件微架构（PE/Cache/数据流）、系统调度 | 逐页死磕公式变量、模块级联依赖与硬件数据流；复核红色疑似错误与密集机制批注；梳理核心架构图读图链。 | 按全局统一符号表、分配字数（参考 40%~45%，4k~5k 字）及跨区答疑补丁，产出**第二章《贡献与创新点》**高保真 XML 片段。 |
| **Subagent-3**<br/>`实验评估与局限专员` | Experimental Setup、Main Results、Ablation、**独立 Limitations 章节**、Conclusion | 核准实验平台、工艺/频率、基线与指标口径；提取验证结论支援前文疑问；识别是否有独立局限性章节及绿色缺陷标注。 | 按分配字数（参考 20%~25%，2k~2.5k 字），产出**第三章《结果与评估》**（含主结果表、消融分析及**独立局限性完整总结小节**）。 |
| **Subagent-4**<br/>`可追溯线索专员`<br/>*(按需：有橙色标注时启动)* | 全篇所有**橙色标注 (`#f19837`) 所在段落 + References 对应引文** | 执行“三步溯源法”前两步：锚定原文引用角色与用户批注意图，联网检索被引先驱文献（The Former）的底层机理与缺陷。 | 按分配字数（参考 15%~20%，1.5k~2k 字），完成第 3 步“反观本篇折中与局限（The Latter）”，产出**第四章《待深入与可追溯线索》**。 |

### 典型参考模式 B：大部头综述型长文（Survey / Review） —— “1 全局分类学 + N 流派动态编组”

| Subagent 角色（参考建议） | 负责原文范围（按综述实际结构动态择优） | 第 1 步任务（精读上报《情报卡》） | 第 3 步任务（依指令写《章节高密稿》） |
| :--- | :--- | :--- | :--- |
| **Subagent-S0**<br/>`全文脉络与分类学总览专员`<br/>*(必配：提供全局视角)* | **通览全篇综述骨架** + 深入精读引言、演进历史、顶层分类学框架（Taxonomy） | 1. 提炼全文顶层分类学知识树与各章节演进关系；<br/>2. 制定全局术语表与跨流派对比维度基准；<br/>3. 定位全篇批注与跨节呼应关系。 | 产出**开篇原生思维导图（`mindmap`）、全文主线概览，以及开篇章节《领域发展脉络与分类学总览》**。 |
| **Subagent-S1..Sn**<br/>`技术流派专员 1..n` | 按综述核心分类大章择优切分（每人负责 1~2 个紧密关联的技术流派，约 8~12 页/人） | 提炼所辖流派的核心机理、子分支演进、代表性里程碑工作（Representative Works）及优劣折中，解析本区批注。 | 严格按字数配额，以“简洁、逻辑清晰”为准则，产出各技术流派章节高密度综述（拒绝流水账罗列）。 |
| **Subagent-Sk**<br/>`横向对比与挑战专员` | 跨流派对比讨论、总结大表、Open Challenges / Future Directions | 提取跨流派多维对比维度（硬件开销/能效/适用场景/泛化壁垒）；梳理未决难题与未来趋势。 | 产出《跨流派多维横向对比矩阵》与最终章《开放挑战与未来趋势》。 |

## 三、 三步走双向闭环工作流与通信模板

### 第一步：并行侦察与结构化情报上报（Subagents → 主 Agent）

主 Agent 通过 `invoke_subagent` 并行启动 `Subagent-0` 与各局部专员 `Subagent-1..N`。各子 Agent 完成阅读后，**严禁直接输出长篇笔记草稿**，必须按以下结构（控制在 500~800 字）向主 Agent 汇报：

#### 1. `Subagent-0` 专属上报格式：《全局脉络与拓扑报告》
```markdown
### 【全局脉络与拓扑报告】Subagent-0（全文视角）
1. **全景论文地图（Paper Map）与核心接力链**：
   - [研究问题 → 方法一 → 留下的新瓶颈 → 方法二 → 实验验证与结论边界；或综述的顶层 Taxonomy 分类树]
2. **跨章节强耦合与隐性呼应清单**：
   - `[耦合点 1]`：第 X 节的 [某假设/设计] 决定了第 Y 节的 [某机制]，并在第 Z 节 [Fig./Table] 验证；
3. **全局统一符号与核心术语表**：
   - `符号/缩写 -> 标准中文译名与物理含义`（供主 Agent 统一下发给各局部专员）
4. **跨页紫色疑问全局定位导航**：
   - `[annotation_key] (P.xx 提问)` -> 答案线索位于 `P.yy 第 Z 节 / Fig. k`
5. **开篇思维导图（mindmap）与主线概览建议骨架**：
   - [给出 3~4 层 mindmap 树状节点草案]
```

#### 2. 局部专员 `Subagent-1..N` 上报格式：《区块精读情报卡》
```markdown
### 【区块精读情报卡】Subagent-X（负责范围：P.xx ~ P.yy，章节：xxx）
1. **本区核心论证链**：
   - 承接前提：[上一节遗留什么问题]
   - 核心机制/推导：[本区提出什么观察/算法/微架构，各子模块依赖顺序]
   - 导出结果/新瓶颈：[解决了什么，又引出了什么新问题留给后文]
2. **关键符号、公式与必选图表**：
   - 核心符号定义：`符号 -> 物理含义/维度`
   - 关键公式：`Eq.(x) (P.xx)：输入/输出/硬件或数学作用`
   - 推荐插图：`Fig. x / Table y (P.xx)：展示内容与读图重点`
3. **本区 Zotero 标注逐条核验表**：
   - `[key] | 颜色 | 页码 | 用户批注原话摘要 | 原文核验结论 | 建议形态(正文段落 / 💡关键理解块 / 🔍存疑块 / 第四章) | 是否存在排版分歧需向用户提问`
4. **跨区协同请求（悬念与待查项）**：
   - [本区无法独立回答的疑问或引用的后文模块，请求主 Agent 结合 Subagent-0 报告回传答案]
```

---

### 第二步：全局统筹、用户交互决策与指令回传（主 Agent ↔ 用户 → Subagents）

主 Agent 汇总 `Subagent-0` 的全局报告与各局部专员的《情报卡》（此时主 Agent 上下文极为清爽）：
1. **对齐森林与树木**：将 `Subagent-0` 的全局耦合关系、跨页答案定位与各局部专员的悬念精准配对；
2. **规划脉络与字数总盘**：确定全文各级标题、统一符号表，并按总字数预算（常规顶会 8,000~12,000 字，综述 8,000~15,000 字）为每个局部专员切分**硬性字数区间**；
3. **向用户发起 `ask_question` 交互裁决**：汇总全篇存在排版分歧的高价值批注点，一次性调用 `ask_question` 请用户裁决“旁路高亮块 vs 融入正文”（若当前为“阅读总结”阶段，则直接向用户输出高质量总结与答疑；若进入“计划/撰写”阶段，则在获取用户选择后进入下一步）；
4. **复用原 Subagents 下发《定稿提炼指令单》**：主 Agent 使用 `send_message` 唤醒**原局部专员**（直接利用其上下文中已驻留的该区块高清 PDF 原文记忆，零重复读取开销！）：

```markdown
### 【定稿提炼指令单】致 Subagent-X
1. **归属章节与小节结构**：
   - 请撰写：`<h1>...</h1>` 下的 `<h2>（一）...</h2>` 至 `<h2>（x）...</h2>`
2. **硬性字数预算**：
   - 本部分严格控制在 **[XXXX ~ YYYY] 汉字**，聚焦核心推导与机制，严禁超支膨胀。
3. **全局统一符号与承接约束（源自 Subagent-0 全局视角）**：
   - 统一术语与符号：[列出必须统一的术语/变量名]
   - 承上启下要求：开头需自然承接 [前章结论]，结尾需点出 [留给后章的瓶颈/呼应点]。
4. **跨区疑问闭合补丁**：
   - 你在 P.xx 报告的疑问 `[key]`，经全局定位在 P.yy 核实，完整结论为：[具体结论]。请在该批注落点处直接结合此结论完成闭环解答。
5. **标注落点与用户排版裁决（强制兑现）**：
   - `[key_1]`：用户已裁决采用 **【💡 关键理解】旁路高亮块**，保留原话“[原话]”并紧邻扩展；
   - `[key_2]`：用户已裁决 **融入正文自然段落**；
   - `[key_3]`：必须使用的原图 `Fig. x (P.xx)`，图注编号定为 `图 N`。
```

---

### 第三步：高密内容撰写与主 Agent 终审合龙（Subagents → 主 Agent → 飞书）

1. **各局部 Subagent 交付（写血肉）**：
   - 依据脑中高清原文细节与《定稿提炼指令单》，产出**零幻觉、符合字数配额、严格嵌入批注原话**的章节 XML 片段（遵循 [note-template.xml](note-template.xml)）；
   - 附带《本区标注最终落点核对表》（`annotation_key | 最终状态 | 所在段落/块位置`）。
2. **主 Agent 终审合龙（搭骨架与统一润色）**：
   - **撰骨**：结合 `Subagent-0` 报告，撰写开篇标题、元数据、`🎯 论文主线` Callout 以及 `<whiteboard type="mermaid">` 开篇原生思维导图；
   - **缝合**：拼接各章节 XML 片段，精修章节交界处的过渡句，消除多 Agent 拼接割裂感，并将所有“图 x / 表 y”统一转换为飞书 Block Anchor 超链接；
   - **逻辑与去 AI 味审校**：对照全局论文地图复核因果顺序，对合并后的全文统一执行 `humanizer-zh` 语言审校，确保通篇文风专业一致；
   - **全局标注审计与飞书写入**：汇总核对全部 Zotero 标注 100% 落位后，由主 Agent 唯一执行飞书文档创建/更新与回读验证。
