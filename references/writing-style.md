# 笔记行文与排版风格

## 总体气质

写成供自己后续复习和推导的技术笔记，不写成论文摘要拼接，也不写成面向大众的泛科普。语言专业、直接、紧凑，但关键因果、公式和实验口径必须完整。

## 组织逻辑

- 外层固定使用“背景知识与问题定义—贡献与创新点—结果与评估”。
- 内层跟随论文自身的叙事和技术依赖：论文先讲系统瓶颈再引出算法，笔记也保持该顺序；后续模块依赖前述概念时，不为凑模板而提前。
- 按内容需要保留“问题 → 原因 → 方案 → 结果”的解释链，不要求每段填满固定模板或以边界提醒收尾。单一机制用连贯短段落，递进主题用次一级标题，独立并列项用飞书原生列表；不要用圈号和换行制造碎片化。
- 论文原文重复或跳跃时可以合并重排，但不得改变依赖关系或制造原文没有的因果。

## 开头

依次给出：

1. 原论文标题。
2. 作者、机构、会议/期刊和年份。
3. 一段“论文主线”概览，按论文自身顺序说明问题如何提出和分析、方法如何解决、是否引出新问题及后续如何承接、最终结果和结论边界。
4. 多阶段论文使用“全文主线”提示块或概览表，把这条问题接力链明确呈现；单一方法论文可以保持为紧凑段落。

不要用“本文具有重要意义”“随着技术飞速发展”等空泛开场。

不要把多阶段论文压缩成“提出 A、B、C 三个贡献，结果提升 X”的并列摘要。论文若按“问题 → 分析 → 技术一 → 新瓶颈 → 技术二 → 结果”推进，开篇就应复现这条推进链；后文再按同一顺序展开细节。

## 技术解释

- 先交代公式或模块为什么出现，再解释它如何工作。
- 公式后说明变量、输入输出、执行顺序和作用；避免“公式如下”后直接跳走。
- 数据流要说清输入、缓存、计算、恢复、输出，以及 batch、并行、串行和流水分别发生在哪里。
- 对比前作时指出比较维度，不使用“更先进”“更高效”替代具体差异。
- 用户批注及其答案在相关正文形成完整、可辨识的解释单元。正文位置遵循论文顺序，表达优先沿用用户原话与思路；紧邻补充必要解释，避免混杂或拆散。

## 批注中的关键理解

用户在批注中写下的关键理解本身就是笔记内容，不只是写作提示。将它放到论文最相关的背景、贡献或评估位置，并结合原文补足上下文。

- 尽可能保留批注原句、术语和思考顺序，采用“用户理解经轻度润色 → 紧邻补充必要解释”的形式。保留比较、反例、计算、问题转结论和设计取舍；不要用自己的抽象总结替代。
- 每条实质批注有完整落点，通常为相关小节的独立短段落；重要对比、个人判断或扩展思考可用飞书高亮块。无需全部加“批注”标签或括号，也不将内容杂糅到其他论述。若理解有误，保留原问题的关注点，明确纠正与原因，避免将错误原话当事实。
- 可以简洁，但只能删除重复和无信息措辞，不能删掉批注中真正的解释关系。若一条批注包含多个相互依赖的判断，直接把这些关系写出来，不要让读者自行补全。
- 如果正文位置有限，将完整理解放入相邻小节或旁路提示块，并在主段落留下清晰指向。
- 去 AI 味审校不得削弱这部分内容；审校后重新检查因果、条件、数量关系和影响是否仍然完整。

## 结果解释

- 先给实验设置和比较口径，再给数字。
- 表格后解释数字支持的结论。只有指标易混、对照同时改变因素或统计解释会失真时，简短补出必要限定；不要每段列“不能推出什么”。
- 区分实测、综合、模拟、归一化和自行推算。
- 分析消融时说明每一项技术接住了哪个瓶颈，以及瓶颈是否转移。
- 精度、性能、能效和面积不要互相替代；明确代价与收益是否在同一基线下。

## 待深入与可追溯线索

待深入事项、橙色标注、扩展阅读和仍需核对的外部资料不属于论文的结果评估。存在实质内容时，在结果评估后单列“第四章：待深入与可追溯线索”。

- 每条线索说明它要补什么知识、与本文哪一处有关，以及优先查阅的论文、代码、手册或标准。
- 不把单个局部疑问重新搬到本章；能在正文就地解释的内容仍留在相关方法或结果旁。
- 没有待深入内容时删除整章，不保留空标题。

## 格式

- 使用清晰的标题层级和横向分隔线组织大块内容。
- 用表格承载多维对比、执行阶段或指标口径，不用表格承载需要连续解释的因果链。
- 对黄色重点适量使用**加粗**、下划线或提示块；强调关键短语，不整段加粗。
- 高亮块可承载用户完整批注、重要概念对比、独立延伸或真实疑点；选择它是为了集中理解，不把每条标注都做成提示块。
- 图片紧邻解释，图注格式包含“笔记图号（原文 Fig./Table 编号）：该图帮助看什么”。
- 不默认创建单独的“问题清单”“批注汇总”或“证据来源”章节。

## 去除 AI 痕迹

完成技术内容初稿后，调用 `humanizer-zh` 做语言审校。它只负责改善表达，不负责重组论文论证。删除或改写：

- “综上所述”“值得注意的是”“不可忽视的是”等无信息连接词。
- 每节末重复一次前文内容的机械总结，以及反复出现的“不是……”“不能推出……”“尚未证明……”纠偏句。优先直接定义机制和结论，必要限制仅在相关位置说明一次。
- 没有技术含义的三段式排比和夸张评价。
- “从某种意义上说”“不仅……而且……”等拖长句子的套式。
- 大量括号、引号或“注：”包裹本可直接写进正文的内容。
- 把简单关系命名为“正交关系”“协同范式”等不必要术语。

学术笔记中的“人性化”有明确边界：保持研究语气、技术术语、公式和论证秩序，不加入闲聊、幽默、随意第一人称、故意混乱或不完整句子。去 AI 味的目标是让句子像认真阅读论文后写下的判断，而不是让它像社交媒体文字。

润色顺序固定为：

1. 完成全文理解、三大章节结构和技术初稿。
2. 用 `humanizer-zh` 删除填充短语、宣传性形容词、模糊归因、机械连接和重复结论。
3. 对照润色前版本检查是否删掉条件、改变因果、弱化限定或引入新观点。
4. 通过技术准确性和结构连贯性检查后，才写入飞书。

## 修订已有笔记

- 把用户人工修改视为当前风格的最高优先级样本。
- 先读取最新版，识别用户新增、删减和重新排序的内容。
- 用户后续提出局部文字建议时，以最新文档中唯一出现的旧文本为锚点，使用文本片段级 `str_replace` 改写；pattern 要包含足够上下文。
- 禁止用 `block_replace` 或 `overwrite` 替换局部建议所在的 block，即使该 block 只有一个待改句子；网页端已有的其他修改必须原样保留。
- 旧文本不存在、重复出现或无法唯一定位时，不猜测 pattern，也不退回 block 替换；在对话中展示拟改内容并等待用户指定准确原文。
- 只有用户明确要求整篇替换并确认允许放弃现有内容时，才允许 overwrite；“写入飞书”本身不构成整篇覆盖授权。
- 保留用户有意留下的个人判断，但纠正明确事实错误时说明原因。

## 最终检查

- 标题结构清楚，但没有为了整齐而切出过多碎小节。
- 每段都有信息推进，不重复上段结论。
- 关键数据、公式和图表均能回到原论文。
- 核心问题得到解释，剩余问题明确而具体。
- 文字足够简洁，同时把关键理解直接说清，不让读者依赖暗示或猜测。
