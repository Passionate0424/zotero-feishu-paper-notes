# 笔记行文与排版风格

## 总体气质

写成供自己后续复习和推导的技术笔记，不写成论文摘要拼接，也不写成面向大众的泛科普。语言专业、直接、紧凑，但关键因果、公式和实验口径必须完整。

## 组织逻辑

- 外层固定使用“背景知识与问题定义—贡献与创新点—结果与评估”。
- 内层跟随论文自身的叙事和技术依赖：论文先讲系统瓶颈再引出算法，笔记也保持该顺序；后续模块依赖前述概念时，不为凑模板而提前。
- 按内容需要保留“问题 → 原因 → 方案 → 结果”的解释链，不要求每段填满固定模板或以边界提醒收尾。单一机制用连贯短段落，递进主题用次一级标题，独立并列项用飞书原生列表；不要用圈号和换行制造碎片化。
- 论文原文重复或跳跃时可以合并重排，但不得改变依赖关系或制造原文没有的因果。

## 篇幅预算与字数约束 (Word Count & Budget Constraints)

专业学术精读笔记必须追求**“高信息密度、直接紧凑、深度透彻”**，严禁失控膨胀为泛百科全书：

1. **整篇笔记总字数基准（以中文字符计）**：
   - **标准顶会论文（正文 10~14 页）**：全文黄金字数控制在 **8,000 ~ 12,000 汉字**（实测约 1 万字为最优区间，兼顾全部图表拆解与深度疑问闭环）；
   - **短篇/Workshop 论文（6~8 页）**：控制在 **5,000 ~ 8,000 汉字**；
   - **长篇顶会研讨论文（10~15 页）**：控制在 **8,000 ~ 12,000 汉字**（黄金比例 2:4:2:2）；
   - **大部头综述型论文（Survey / Review / 20~50+ 页）**：控制在 **8,000 ~ 15,000 汉字**，严禁按百科教材平铺导致失控膨胀，以“简洁、逻辑清晰地概述本文分类与脉络”为准绳。

2. **各章节字数预算分配（以研究型论文万字黄金比例 2:4:2:2 为例）**：
   - **第一章：背景知识与问题定义**：占比约 **15% ~ 20%（约 1,500 ~ 2,000 字）**，聚焦痛点、系统瓶颈与动机；
   - **第二章：核心贡献与创新点（软硬件架构）**：占比约 **40% ~ 45%（约 4,000 ~ 5,000 字）**，为全文重心，数学公式、微架构、PE 与数据流必须讲深讲透；
   - **第三章：结果与评估**：占比约 **20% ~ 25%（约 2,000 ~ 2,500 字）**，聚焦基线控制、指标口径与消融分析；
   - **第四章：待深入与可追溯线索**：占比约 **15% ~ 20%（约 1,500 ~ 2,000 字）**，概括浓缩为 3~5 条独立闭环专题。

## 开头

依次给出：

1. 原论文标题。
2. 作者、机构、会议/期刊和年份。
3. 一段“论文主线”概览（约 250 ~ 400 汉字）：按论文自身因果顺序说明问题如何提出和分析、方法如何解决、是否引出新问题及后续如何承接、最终结果和结论边界，复现问题接力链。
4. “核心贡献概括”提示块：直接提炼原论文引言（Introduction）结尾作者自述的核心贡献列表，忠实对齐原著自身列出的条目与项数，使用带有加粗主题词的列表呈现，让读者一眼看清作者声称的核心交付物。
5. “核心局限性概括”提示块（可选）：若原论文分析或讨论了局限性、适用边界或失效场景，紧随核心贡献之后整理出条理清晰的局限性概括列表，方便读者开篇快速把握技术边界与适用工况。
6. 飞书原生思维导图（`<whiteboard type="mermaid">` 内置 `mindmap`）。

开篇的“论文主线”、“核心贡献”与“局限性概括”形成全局视角互补：
- **论文主线**：展现动态的因果演进流（为什么做、各项技术如何接力解决新瓶颈）；
- **核心贡献**：展现静态的硬核交付物清单（作者具体宣称做出了哪几项实质成果）；
- **局限性概括**：展现清晰的技术有效边界（适用场景假设、Corner Case 与未决瓶颈）。

不要用“本文具有重要意义”“随着技术飞速发展”等空泛词句开场。

## 技术解释

- 先交代公式或模块为什么出现，再解释它如何工作。
- 公式后说明变量、输入输出、执行顺序和作用；避免“公式如下”后直接跳走。
- 数据流要说清输入、缓存、计算、恢复、输出，以及 batch、并行、串行和流水分别发生在哪里。
- 对比前作时指出比较维度，不使用“更先进”“更高效”替代具体差异。
- 用户批注及其答案在相关正文形成完整、可辨识的解释单元。正文位置遵循论文顺序，表达优先沿用用户原话与思路；紧邻补充必要解释，避免混杂或拆散。

### 数学公式与符号排版规范

为确保技术符号在飞书文档中稳定呈现，避免符号丢失或 XML 解析崩溃，成稿时严格区分并执行以下两类排版规则：

1. **数学公式与含上下标推导（数学模式）**：
   - 严禁在飞书文档中裸写 `$` 或 `$$` 定界符。飞书 API 无法识别 Markdown 形式的公式语法，会导致页面留存裸露的美元符号。
   - 凡涉及变量上下标、数学推导或符号关系（如 $s_v > s_a$），一律使用飞书原生 `<latex>...</latex>` 标签包裹。
   - 关系与比较运算符必须使用标准 LaTeX 命令，避免 `<` 被 XML 解析器误判为标签起始符号：
     - 大于号写作 `\gt`（例如 `<latex>s_v \gt s_a</latex>`）；
     - 小于号写作 `\lt`（例如 `<latex>s_v \lt s_a</latex>`）；
     - 大于等于写作 `\ge` 或 `\geq`；
     - 小于等于写作 `\le` 或 `\leq`。
   - 跨行或独立的重点推导公式，使用独占段落的 `<p><latex>...</latex></p>`。

2. **程序代码、寄存器字段与硬件参数（代码模式）**：
   - 算法超参数、硬件信号、寄存器位宽与条件分支，一律使用 `<code>...</code>` 标签包裹（例如 `<code>clk_en</code>`、`<code>stride &lt; 4</code>`、`<code>dim &gt;= 512</code>`）。
   - 小于号与大于号按 XML 基础规则转义为 `&lt;` 与 `&gt;`。
   - 飞书会将 `<code>` 渲染为带有微灰底色的等宽字符徽章，排版紧凑且字符完全保真。

## 批注中的关键理解

用户在批注中写下的关键理解本身就是笔记内容，不只是写作提示。将它放到论文最相关的背景、贡献或评估位置，并结合原文补足上下文。

- 尽可能保留批注原句、术语和思考顺序，采用“用户理解经轻度润色 → 紧邻补充必要解释”的形式。保留比较、反例、计算、问题转结论和设计取舍；不要用自己的抽象总结替代。
- 每条实质批注有完整落点，通常为相关小节的独立短段落；重要对比、个人判断或扩展思考可用飞书高亮块。无需全部加“批注”标签或括号，也不将内容杂糅到其他论述。若理解有误，保留原问题的关注点，明确纠正与原因，避免将错误原话当事实。
- 可以简洁，但只能删除重复和无信息措辞，不能删掉批注中真正的解释关系。若一条批注包含多个相互依赖的判断，直接把这些关系写出来，不要让读者自行补全。
- 如果正文位置有限，将完整理解放入相邻小节或旁路提示块，并在主段落留下清晰指向。
- 去 AI 味审校不得削弱这部分内容；审校后重新检查因果、条件、数量关系和影响是否仍然完整。

## 结果解释

- 先给实验设置和比较口径，再给数字。
- 表格后解释数字支持的结论。只有指标易混、对照同时改变因素或统计解释会失真时，简短补出必要限定；不要每段列“不能推出什么”。
- 区分实测、综合、模拟、归一化和自行推算。
- 分析消融时说明每一项技术接住了哪个瓶颈，以及瓶颈是否转移。
- 精度、性能、能效和面积不要互相替代；明确代价与收益是否在同一基线下。
- **独立局限性章节的处理**：若论文设有独立的 Limitations 章节，笔记不得以“正文已有提及”为由跳过或拆散。必须在第三章作为独立小节，系统化交代论文的适用场景假设、硬件部署壁垒、数据长尾敏感度及未覆盖的 Corner Cases，保持技术严谨度。

## 待深入与可追溯线索

待深入事项、橙色标注、扩展阅读和仍需核对的外部资料不属于论文的结果评估。存在实质内容时，在结果评估后单列“第四章：待深入与可追溯线索”。

- 每条线索说明它要补什么知识、与本文哪一处有关，以及优先查阅的论文、代码、手册或标准。
- 每条线索必须严格践行“被引先驱文献/方法真实机理（前者） → 反观论文本身改进、折中与局限（后者）”的对比闭环，概括浓缩整合为独立技术专题。
- 融入用户在批注中提出的批判性疑问（如静态假设在长尾/OOD 场景下的泛化边界、预计算与片上存储折中、与同源技术路线的本质差异等），形成高水平学术反思。
- 不把单个局部疑问重新搬到本章；能在正文就地解释的内容仍留在相关方法或结果旁。
- 没有待深入内容时删除整章，不保留空标题。

## 格式

- 使用清晰的标题层级和横向分隔线组织大块内容。
- 用表格承载多维对比、执行阶段或指标口径，不用表格承载需要连续解释的因果链。
- 正文主线依层级适度强调：黄色大于蓝色，各颜色内高亮高于下划线；高优先级内容适量使用**加粗**或表格突出，强调关键短语，不整段加粗。
- 高亮块可承载用户完整批注、重要概念对比、独立延伸或真实疑点；选择它是为了集中理解，不把每条标注都做成提示块。
- 图片紧邻解释，图注格式包含“笔记图号（原文 Fig./Table 编号）：该图帮助看什么”。
- 不默认创建单独的“问题清单”“批注汇总”或“证据来源”章节。

### 正文图表交互超链接规范 (Interactive Anchor Links)
在长篇技术精读笔记中，正文提及的所有图表，不得使用纯文本！
- 凡出现“图 x”、“表 y”、“如图 6 所示”等表述，必须原位转换为指向飞书原生 Block ID 的 Anchor 超链接：
  `<a href="文档URL#block_id">图 x</a>`
- 确保读者在长达数万字的笔记中阅读时，点击即可平滑跳转并高亮对应图表，保障沉浸式精读心流。

### 开篇飞书原生思维导图（Mindmap）规范
在每篇笔记开篇（元数据与主线概览之后、第一章正文之前），必须插入飞书原生思维导图块（`<whiteboard type="mermaid">`）：
- 语法统一采用 Mermaid `mindmap`；
- 节点层级控制在 3~4 层，突出分类学核心或因果技术链路；
- 节点文本精炼聚焦，避免冗长句子；
- 在飞书文档中将自动渲染为可交互、可缩放的原生画板思维导图，保障全篇知识的顶层视觉导航。

## 综述型论文（Survey / Review）组织与写作规范

当精读对象为综述论文时，严格执行以下自适应准则：

1. **破除四大章节教条**：
   - 严禁将综述强行按“背景—微架构—实验消融”切割；
   - 直接继承并提炼原著的**分类学体系（Taxonomy）**作为章节骨架（例如：按技术路线演进、按应用场景分派、按系统分层展开）；
2. **篇幅与信息密度控制**：
   - 综述往往篇幅冗长（动辄 30~50+ 页），严禁逐节平铺扩写成百科教材；
   - 总字数控制在 **8,000 ~ 15,000 汉字**，以“**简洁、逻辑清晰地概述本文核心脉络**”为最高准则；
   - 重点提炼：分类划分准则、各技术流派的机理突破与局限折中、最具代表性的里程碑工作（Representative Works），避免罗列泛泛论文清单；
3. **多维横向对比矩阵**：
   - 必须设计结构化横向比较表格，从设计空间、硬件/算力代价、适用工况、泛化瓶颈等多维度拉通对比各流派；
4. **开放挑战与未来趋势**：
   - 综述末尾单列独立章节，提炼原著指出的未决学术难题、工程实现壁垒与未来探索方向。

## 去除 AI 痕迹

完成技术内容初稿后，调用 `humanizer-zh` 做语言审校。它只负责改善表达，不负责重组论文论证。删除或改写：

- “综上所述”“值得注意的是”“不可忽视的是”等无信息连接词。
- 每节末重复一次前文内容的机械总结，以及反复出现的“不是……”“不能推出……”“尚未证明……”纠偏句。优先直接定义机制和结论，必要限制仅在相关位置说明一次。
- 没有技术含义的三段式排比和夸张评价。
- “从某种意义上说”“不仅……而且……”等拖长句子的套式。
- 大量括号、引号或“注：”包裹本可直接写进正文的内容。
- 把简单关系命名为“正交关系”“协同范式”等不必要术语。

学术笔记中的“人性化”有明确边界：保持研究语气、技术术语、公式和论证秩序，不加入闲聊、幽默、随意第一人称、故意混乱或不完整句子。去 AI 味的目标是让句子像认真阅读论文后写下的判断，而不是让它像社交媒体文字。

润色顺序固定为：

1. 完成全文理解、三大章节结构和技术初稿。
2. 用 `humanizer-zh` 删除填充短语、宣传性形容词、模糊归因、机械连接和重复结论。
3. 对照润色前版本检查是否删掉条件、改变因果、弱化限定或引入新观点。
4. 通过技术准确性和结构连贯性检查后，才写入飞书。

## 修订已有笔记

- 把用户人工修改视为当前风格的最高优先级样本，保留用户有意留下的个人判断，仅在纠正明确事实错误时说明原因。
- 飞书局部修订的技术操作严格执行 [SKILL.md](../SKILL.md) 第 8 节规定：以最新文档中唯一出现的旧片段为锚点，仅使用 `str_replace` 精确替换（严禁使用 `block_replace` 或未经明确授权的 `overwrite`，杜绝破坏用户在网页端补充的内容；无法唯一定位时在对话中给出建议并等待用户指定原文）。

## 最终检查

- 标题结构清楚，但没有为了整齐而切出过多碎小节。
- 每段都有信息推进，不重复上段结论。
- 关键数据、公式和图表均能回到原论文。
- 核心问题得到解释，剩余问题明确而具体。
- 文字足够简洁，同时把关键理解直接说清，不让读者依赖暗示或猜测。
